------------------------------------------------------------------------------
From results/tmi/day14_locked_params.json:
  alpha = 1.6667   beta = 2.1667   kappa = 18.407      -> LOCKED (Fukushima
        transfer; do NOT retune -- Day-16 cross-domain test depends on it).
  clamp = OFF (enable_panic_clamp=False)               -> input for today.
  CMC   = 0.00                                          -> PROVISIONAL.

CMC=0.00 is treated as a TOPOLOGY ARTIFACT, NOT an estimate. Day-14's misfit was
dominated by topology-inflated outer over-evacuation (sigma-driven, camp
adjacency); to keep TOTAL evac in band the optimiser drove CMC to the floor,
which removed the Friday departure spike (inner-by-t10 70% vs target >77%) and
produced a wrong-signed timing Zeigler. CMC is the System-1 term in
   P_move = (1-P_S2)*CMC + P_S2*sigma
and at the Friday conflict peak (c=1.0) Omega=exp(-beta*c) collapses, so
P_S2 -> ~0 and (1-P_S2) -> 1: the term (1-P_S2)*CMC is MAXIMAL exactly at the
threat peak. CMC is therefore the mechanism for prompt flight on Friday. It must
be RE-FIT on v2 with departure timing as a PRIMARY objective (Task B); 0.00 is a
starting point to be replaced, not confirmed.

0.3  RETURN-MECHANISM SURFACE (Task C insertion points)
------------------------------------------------------------------------------
- Person has `home_location` (flee/flee.py __slots__, set at construction).
- flee/flee.py Person.evolve(): draws random()<movechance, then selectRoute()
  and take_next_step(). One-way today: camp agents never leave because...
- flee/moving.py calculateMoveChance(): for camp/idpcamp agents it returns
  (a.location.movechance, 0.0) and camp_movechance=0.0 -> agents stay. This is
  the cleanest insertion point: behind enable_return, give camp agents a
  RETURN movechance when (a) home conflict has recovered and (b) P_S2 is high
  (deliberative). Return is S2-driven (the theoretical claim).
- Homeward routing: flee/moving.py getEndPointScore() / selectRoute() choose by
  endpoint score (camps + low conflict favoured). For a `returning` agent we bias
  the score toward home (closer-to-home endpoints up-weighted, camps penalised).
  Add a `returning` slot to Person (default False).
- Horizon: conflicts.csv already DECAYS to 0 by t=19 (t10=1.0 peak -> t16=0.10
  Carter -> t19=0.00). Omega=exp(-beta*c) recovers to 1 by t19, so P_S2 recovers
  and return can be S2-driven in the t>=16 window. For the 3-week return curve we
  EXTEND the schedule past T_SCHED with c~0 (return phase). Timestep->real-time:
  simsetting_tmi.yml says 1 step = 6 h; the event spacing (t10 Fri 03-30 ->
  t16 Sun 04-01) is ~8 h/step. We adopt 8 h/step for the return phase (21 days ~=
  63 steps) and document it; week-k boundaries computed from that mapping.
- Guardrail: enable_return defaults False; 84 tests must stay green; add focused
  return tests.

0.6  v2 TOPOLOGY DESIGN (Task A) and why it is zone-independent
------------------------------------------------------------------------------
Build input_data/tmi_v2/ (original tmi/ untouched). Replace the three ADJACENT
camps with three DISTANT directional shelters at real destination cities
(destination_map_g6), each reachable ONLY through the Harrisburg transit hub:
  statecollege_camp (40.793, -77.860)  NW  (~75 mi from plant; 50% flow dir)
  philadelphia_camp (39.953, -75.164)  SE  (~84 mi)
  baltimore_camp    (39.290, -76.612)  S   (~60 mi)
Routes: keep all town-town OSM links; DROP the 3 adjacent camp links; ADD
  harrisburg -> {statecollege,philadelphia,baltimore}_camp at OSM road-km
  (OSRM, scripts/update_tmi_routes_osm_day12 method; haversine*1.3 fallback).
Rationale: every town reaches a camp via town -> ... -> harrisburg -> camp. The
camp leg (~100-150 km) is the SAME for all towns; the town->harrisburg leg
(inner ~10-25 km, outer ~40-66 km) is small relative to it, so nearest-camp
distance is dominated by the common long leg (cross-zone spread well under 2x;
Checkpoint A). The residual gradient (inner closer to the hub than outer) is the
PHYSICAL direction (inner travels less, outer more) and should yield inner >=
outer evac WITHOUT the adjacency inflation -- i.e. it removes the inversion.
HONEST EXPECTATION: with conflict UNIFORM across towns (conflicts.csv identical
columns), the model has no spatial THREAT gradient; the only zonal lever is
hub distance. So v2 should REMOVE the inversion (outer no longer >> inner) and
give inner>=middle>~outer via hub proximity; a strong inner>>outer gradient may
not fully emerge (uniform-threat limitation). Per the guardrail, if the gradient
does not fully correct, that is a real finding (not purely topological) and is
reported, not forced. Network path length (distance_travelled) becomes a clean
Zeigler travel-distance metric in v2 (inner<outer), while plant-referenced dest
displacement is ~uniform (all evacuate far ~60-84 mi -> matches the 85-mi median).
